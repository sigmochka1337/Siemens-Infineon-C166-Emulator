# Структура эмулятора

Основной договор команды находится в [architecture.md](architecture.md),
ограничения CPU — в [cpu_profile.md](cpu_profile.md), работающие формы команд —
в [isa_scope.md](isa_scope.md). Этот файл — краткая карта проекта.

| Владелец | Каталог | Роль |
| --- | --- | --- |
| 1. Executor | `src/executor/` | Исполнение, PSW, PC, порядок работы с операндами; далее стек и EXT |
| 2. Decoder + Fetcher | `src/decoder/` | Выборка 2/4 байт, чистое декодирование, таблица форм, форматирование |
| 3. Memory | `src/memory/` | Единая RAM/GPR/SFR, адресация, bus и безопасный осмотр |
| 4. Debugger | `src/debugger/`, `src/core/`, `tools/` | Цикл шага, сборка объектов, run/step, остановки и trace |

```text
Debugger → CpuCore::Tick
         → Fetch(pc, memory, decoder) → RawInstruction
         → Decode(raw)               → Instruction
         → Execute(instruction, machine) → StepResult
```

Общие типы — `src/common/`, абстрактные контракты — `src/interfaces/`.
Декодер передаёт способы адресации и константы, а не текущие значения регистров.
Только executor меняет PC после исполнения команды. Memory обеспечивает
согласованность регистров с их отображением в RAM/SFR. Core координирует вызовы
и останавливает дальнейшее исполнение при ошибке.

`Snapshot`, `PeekMemory` и `InspectInstruction` предназначены для наблюдения
без гостевых побочных эффектов. `Reset` сбрасывает управляющее состояние,
сохраняя RAM; snapshot не включает RAM и не является сохранением всей машины.

В текущем срезе работают NOP, две формы MOV, ADD reg/reg и JMPR. Полная ISA,
периферия, аппаратный вход в обработчики, интерактивный CLI и step-out пока
не реализованы. Порядок сборки и запуска тестов — в [README](../README.md).
