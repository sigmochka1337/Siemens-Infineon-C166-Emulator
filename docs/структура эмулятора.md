#структура эмулятора

#основной цикл 
PC → Fetch → (word, length, pc_start) → Decode → Instruction → Execute → новое состояние

основной цикл работы эмулятора делится на 3 части:
1. Fetch - извлечение очередной инструкции
2. Decode - разбор инструкции
3. Execute - выполнение опреции и обновление состояния

#задачи Fetch
1. прочитать байты через интерфейс памяти
2. собрать слово с учетом порядка байтов
3. сохранить адрес инструкции
4. передать декодеру слово

#задачи Decode
1. определить тип инструкции
2. проверить корректность инструкции и преобразовать ее во внутреннее представление
3. подготовить данные для Execute: значения регистров, флаги

#задачи Execute
1. выполнить операцию,соответствующую инструкции
2. обновить регистры, флаги, память
3. взаимодействие с модулями устройств ввода-вывода

#состояние процессора
центральная структура данных, хранящая полное состояние эмулируемой машины. В нее входят:
1. регистры общего назначения
2. счетчик команд
3. регистры состояния, флаги
4. поля для обработки исключений: причина, адрес инструкции, статус

#подсистема памяти
задачи:
1. предоставить единый интерфеййс чтения и записи для разной ширины
2. учитывать порядок байтов
3. проверять выравнивание, если этого требует архитектура

#устройства ввода-вывода и MMIO
Периферия моделируется через механизм MMIO: определенные адреса памяти перенаправляются обработчиками устройств. Задачи модуля периферии:
1. принимать обращения по определенным адресам
2. перенаправлять их в обработчики устройств
3. не позволять исполнительному блоку напрямую обращаться к памяти в обход интерфейса памяти (интерфейс памяти — это единственное место, где сосредоточены все правила доступа к адресному пространству. Если исполнительный блок читает или пишет напрямую, эти правила перестают применяться, и эмулятор начинает вести себя непоследовательно.)
