# Краткий справочник C166 для проекта

Это вводная памятка к реализованному срезу. Точные кодировки и поддержанные
формы находятся в [isa_scope.md](isa_scope.md), модель окружения — в
[cpu_profile.md](cpu_profile.md). Источник архитектурных правил — локальный
C166 Instruction Set Manual, а не общие сведения об ассемблере других ISA.

## Регистры и адреса

- `R0..R15` — 16-битные регистры, отображённые в RAM по `CP + 2*n`.
- `RL0..RL7` и `RH0..RH7` — младшие и старшие байты `R0..R7`.
  Запись в одну половину сохраняет вторую.
- `CSP:IP` — сегмент и смещение адреса команды. Физический адрес кода:
  `(CSP << 16) | IP`. DPP в выборке кода не участвует.
- `DPP0..DPP3` — четыре указателя страниц данных; это отдельный механизм
  трансляции логических адресов.
- `CP` выбирает банк GPR, `SP` указывает на системный стек, `PSW` хранит флаги.
  `MDH/MDL/MDC` относятся к умножению и делению, которые пока вне среза.

Команда C166 занимает 2 или 4 байта, IP и словные доступы выровнены по двум
байтам. Данные little-endian. В инструкции `MOV R0,#0x1234` символ `#`
обозначает непосредственную константу; запятая отделяет приёмник от источника.

## PSW

| Бит | Имя | Смысл для арифметических условий |
| --- | --- | --- |
| 0 | N | Знак результата |
| 1 | C | Перенос/заём согласно конкретной операции |
| 2 | V | Знаковое переполнение |
| 3 | Z | Нулевой результат либо специальное правило инструкции |
| 4 | E | Специальный признак конца таблицы; для текущих MOV/ADD исходный операнд равен `8000h` |

Правила обновления задаются отдельно каждой инструкцией. C166 `MOV` меняет
E/Z/N, сохраняя C/V; `ADD` вычисляет E/Z/V/C/N. Остальные биты PSW сохраняются
с учётом аппаратных масок профиля. В будущих ADDC/ADDCB потребуется накопительный
Z, а явная запись PSW имеет отдельные правила. Источник: ISM, стр. 34–38,
41, 43–44, 95.

## Реализованный пример

```text
Адрес  Байты          Инструкция
0000   E6 F0 01 00    MOV R0,#0x0001
0004   E6 F1 02 00    MOV R1,#0x0002
0008   00 01          ADD R0,R1
000A   0D FF          JMPR cc_UC,-1
```

После первых трёх команд `R0=3`, `R1=2`, `IP=000Ah`. JMPR считает смещение
в словах от следующей команды: `000Ch + 2*(-1) = 000Ah`, поэтому последняя
команда повторяет себя. Для завершения демо debugger останавливается перед
адресом `0:000Ah`; для выполнения цикла нужно установить лимит шагов.

Также реализованы `NOP` (`CC 00`), `MOV Rn,Rm` и все 16 условий JMPR.
`cc_Z` проверяет Z, `cc_NZ` — его сброс, `cc_NET` — одновременный сброс Z и E.
Байтовые формы, вызовы функций, возвраты и другие мнемоники из полного
руководства пока не исполняются. Загрузчик работает с сырыми байтами; собственный
ассемблер, линкер и разбор объектных форматов в текущем проекте не реализованы.
