# Fetch + Decode: актуальный контракт

Владелец — участник 2. Интерфейсы: `src/interfaces/fetcher.h`,
`src/interfaces/decoder.h`. Реализация: `src/decoder/fetcher.cpp`,
`src/decoder/decoder.cpp`. Типы: `src/common/instruction.h`.

## Вход и выход

```text
CSP:IP + IMemoryBus + IDecoder
  → Fetcher → Result<RawInstruction>
  → Decoder → Result<Instruction>
  → Executor
```

`RawInstruction` хранит до четырёх байтов, точное число прочитанных байтов и
начальный `CSP:IP`. Валидная C166-инструкция занимает **2 или 4 байта** (ISM,
стр. 36). `Decode` ожидает ровно одну инструкцию; `raw.size` должен совпадать с
длиной кодировки. Короткий массив даёт `kTruncatedInstruction`, избыточный —
`kInvalidArgument` как нарушение API.

`Instruction` содержит мнемонику, длину, исходные байты и адрес, явное условие и
типизированные операнды. Immediate хранится в самой инструкции. ConstantBus,
служебные адреса для констант и снимки значений операндов не используются.

## Выборка без лишних чтений

1. Проверить чётность IP. Нечётный адрес даёт диагностический trap
   `kIllegalInstructionAddress` до чтения памяти.
2. Прочитать первое слово по физическому адресу `(CSP << 16) | IP` с
   `AccessKind::kCode`. DPP для выборки не применяется.
3. Запросить длину через `IDecoder::InstructionLength`. Он использует ту же
   таблицу, что Decode, поэтому второй таблицы длин в Fetcher нет.
4. Для четырёхбайтовой команды прочитать второе слово. Для двухбайтовой больше
   ничего не читать: недоступная память за концом NOP не должна мешать его выборке.
5. Вернуть исходный PC и байты, ничего не исполняя.

Ошибки bus сохраняют исходный код и физический адрес. Ошибка определения длины
получает адрес начала инструкции. Неизвестная текущему subset кодировка даёт
`kUnsupportedInstruction`; это не утверждение о её аппаратной недопустимости.

## Граница сегмента

Fetcher не переносит IP в CSP. Во время code fetch сегменты автоматически не
меняются (SUBS, §4.5, стр. 4-9). Переключение сегмента выполняют соответствующие
инструкции управления потоком.

Двухбайтовая команда на `IP=FFFEh` может быть выбрана без обращения к следующему
сегменту. Четырёхбайтовая команда на этом адресе даёт `kSegmentBoundary` после
первого слова. Это диагностическое ограничение учебного профиля; оно не
выдаётся за описанный руководством аппаратный trap. Что делать при последующем
движении PC, решает executor по общему профилю, а не Fetcher.

## Чистый декодер

Decoder не получает память данных или регистры и не имеет состояния CPU.
Косвенная адресация, short reg, bitoff, pre-decrement/post-increment и EXT
разрешаются при исполнении. Состояние EXT хранится в machine; executor управляет
его изменением и отсчётом 1–4 инструкций. Наличие EXT не меняет чистоту Decode.

`RelativeOperand.words` — знаковое смещение в словах. Цель вычисляет executor
от IP следующей инструкции. Нечётные абсолютные/косвенные цели должны
обрабатываться по правилам trap (ISM, стр. 139–140), а не маскироваться.

`Format` форматирует результат Decode и не читает память или состояние CPU.
Его использует debugger. Точные реализованные формы, кодировки и источники
собраны в [`isa_scope.md`](isa_scope.md).

## Проверка независимо от соседних модулей

`tests/test_decoder.cpp` использует fake `IMemoryBus` с ограниченной картой
доступных байтов. Проверяются нибблы всех GPR, little-endian immediate,
все условия и крайние значения rel8, ошибки входа, фиксированный NOP,
неподдержанные формы, число обращений к памяти и границы кодового сегмента.
Тест не зависит от конкретных `Machine`, `Executor` или debugger.
