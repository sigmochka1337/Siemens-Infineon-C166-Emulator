# Дебаггер эмулятора C166 

Дебаггер управляет выполнением программы в эмуляторе и позволяет смотреть и менять состояние процессора. Сам он инструкции не выполняет, а вызывает компоненты эмулятора:

1. **машину**: память, регистры, PC;
2. **fetcher**: чтение и декодирование инструкции;
3. **executor**: выполнение инструкции.

## Управление выполнением

### Step

Выполнить одну инструкцию. Дебаггер берёт текущий PC, получает по нему инструкцию через fetcher и передаёт её executor'у.

Breakpoint'ы при этом не учитываются, поэтому Step позволяет сойти с точки останова.

### Run

Выполнять инструкции подряд, пока PC не попадёт на breakpoint.

1. Проверка идёт **до** выполнения инструкции, поэтому остановка происходит перед инструкцией с точкой останова.
2. Первая инструкция выполняется без проверки, чтобы можно было продолжить выполнение с текущего breakpoint'а.
3. Чтобы не зависнуть на бесконечной программе, у Run есть ограничение на число инструкций.

## Точки останова

### add_breakpoint

Поставить точку останова по физическому адресу. Адрес должен быть чётным и не выходить за пределы памяти, иначе возникает ошибка.

### remove_breakpoint

Убрать точку останова. Если на этом адресе точки останова нет, возникает ошибка.

## Просмотр состояния

### trace

Вывести в консоль текущее состояние процессора:

- слово состояния **PSW** с флагами (N, C, V, Z и др.);
- **размер стека**;
- значения **всех регистров** (R0–R15, SP, CP, DPP0–DPP3, MDL, MDH и др.).

Используется, чтобы видеть, как меняется процессор после каждой инструкции.

### show_next_instruction (asm)

Показать следующую инструкцию, которая будет выполнена, в виде ассемблера. Инструкция только декодируется, но не выполняется.

## Работа с памятью

### read 8/16

Прочитать из памяти байт (8 бит) или слово (16 бит). Поддерживаются два вида адреса:

1.  **физический** (24 бита) — напрямую;
2. **логический** (16 бит) — переводится в физический через регистры DPP.

### write 8/16

Записать в память байт или слово, по физическому или логическому адресу. Используется, чтобы вручную менять данные во время отладки.

## Работа со стеком

### push

Вручную положить слово на стек: указатель стека SP уменьшается на 2, и значение записывается по новому адресу SP.

### pop

Вручную снять слово со стека: значение читается по адресу SP, затем SP увеличивается на 2.

Push и pop выполняются дебаггером напрямую, без инструкций программы. Они нужны, чтобы во время отладки менять содержимое стека, например подставить адрес возврата.
