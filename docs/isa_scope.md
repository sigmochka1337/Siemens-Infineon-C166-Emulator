# Поддержанные формы ISA

Этот документ задаёт начальный проверенный срез для совместной работы четырёх
участников. Источник кодирования — локальный **C166 Instruction Set Manual,
V2.0, 2001-03**. Номера страниц ниже — печатные. Состав будущего v1 расширяется
построчно; наличие мнемоники в enum не является обещанием её реализации.

## Реализованный начальный срез

В колонках `mask/value` рассматривается первое little-endian слово:
`word = byte[0] | (byte[1] << 8)`. Совпадение: `(word & mask) == value`.
Операнд `n` — приёмник, `m` — источник; в `nm` приёмник занимает старший ниббл.

| Форма | Байты | mask / value | Длина | Выход decoder | Источник ISM |
| --- | --- | --- | --- | --- | --- |
| `NOP` | `CC 00` | `FFFF / 00CC` | 2 | без операндов | стр. 105 |
| `MOV Rn,Rm` | `F0 nm` | `00FF / 00F0` | 2 | два `RegisterOperand`, word | стр. 96 |
| `MOV Rn,#data16` | `E6 (F0+n) lo hi` | `F0FF / F0E6` | 4 | register + immediate word | стр. 96, 132–133 |
| `ADD Rn,Rm` | `00 nm` | `00FF / 0000` | 2 | два `RegisterOperand`, word | стр. 41 |
| `JMPR cc,rel8` | `cD rr` | `000F / 000D` | 2 | поле `condition`, один `RelativeOperand` | стр. 38, 91, 140 |

`n,m = 0..15`. `rr` — знаковое 8-битное смещение в словах. Executor считает цель
от следующей инструкции: `next_ip + 2 * displacement`. Перенос в CSP не делается.
Все 16 значений `c` определены таблицей условий ISM; `cc_NET` использует флаг E.

`MOV reg,#data16` целиком имеет длину 4 и определяется метаданными
`mask=00FF/value=00E6`. На этапе Decode пока поддержаны только `reg=F0..FF`.
Другие приёмники этой формы дают `kUnsupportedInstruction`, не исполняются.

Все остальные формы сейчас возвращают `kUnsupportedInstruction`. Неподдержанная
кодировка может быть допустимой C166-инструкцией. `CC xx`, где `xx != 00`,
отвергается как несоответствие описанному фиксированному формату NOP.

## Дальнейшее расширение

| Группа | Планируемые формы | Что согласовать до реализации |
| --- | --- | --- |
| Пересылки | MOV/MOVB: short reg, direct, indirect | resolver, SFR byte-write, RL/RH |
| Арифметика | ADDC/SUB/SUBC/CMP, byte-варианты, NEG | PSW, sticky Z, E, сохранение флагов |
| Логика | AND/OR/XOR/CPL, shifts, rotates | точные формы и флаги по каждой инструкции |
| Стек и управление | PUSH/POP, CALLA/I/R/S, PCALL, RET/S/P, JMPA/I/S | short reg шире GPR, stack checks, события call/return |
| Битовые операции | JB/JNB/JBC/JNBS, BSET/BCLR | bitoff resolver, условное изменение бита |
| EXT | EXTP/EXTS/EXTPR/EXTSR/EXTR | диапазон 1–4, единый счётчик, ESFR |
| Умножение/деление | MUL/MULU/DIV/DIVU/DIVL/DIVLU | MDL/MDH/MDC, специальные флаги |
| Traps/interrupts | TRAP/RETI и аппаратный вход | отдельный объём: начальный срез останавливается с диагностикой |

`CALL` — обобщённое название семейства, отдельной машинной команды с таким
именем здесь нет. Правильная мнемоника условного перехода с установкой бита —
`JNBS`, не `JNBC`.

EXT-команды — самостоятельные инструкции с диапазоном **1–4 следующих
исполненных инструкций**, задаваемым `#irang2`. EXTP/EXTS переопределяют DPP;
R-варианты дополнительно выбирают ESFR. Состояние принадлежит machine, изменение
и отсчёт — executor. Decoder остаётся чистым. Источник: ISM, стр. 39, 78–85, 138.
Поддержка этих команд пока запланирована, а не реализована.

## Правило добавления формы

Одна строка manifest должна иметь точную кодировку и ограничения полей, длину
2 или 4, типы операндов, источник, статус decoder и executor. Сначала добавить
тест байтов и полей; затем тест семантики по входному/выходному состоянию; затем
сквозной тест через `CpuCore`. Общий результат команды считается готовым после
поддержки обоими модулями.

## Программа для первого сквозного теста

```text
E6 F0 01 00    MOV R0,#0x0001
E6 F1 02 00    MOV R1,#0x0002
00 01          ADD R0,R1
0D FF          JMPR cc_UC,-1
```

После первых трёх инструкций `R0=3`, `R1=2`, `IP=000Ah` при точке входа `0:0`.
Последняя команда образует цикл по собственному адресу; debugger должен
ограничивать число шагов или останавливаться перед ней по заданному адресу.
