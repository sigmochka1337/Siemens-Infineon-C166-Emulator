# Область инструкций v1

Документ фиксирует, какие мнемоники попадают в первую версию декодера и под
какой компонент ТЗ они относятся. Кодирование (байты опкодов) здесь намеренно
**не заполнено**: его нужно сверить с Instruction Set Manual, а не набирать по
памяти. Один неверный байт в таблице — это неверный дизассемблер и неверная
эмуляция, поэтому таблица заполняется построчно с указанием источника.

## Как читать таблицу

- **Мнемоники** — из ТЗ, раздел 3.2 (ALU, BitProcessor, Stack + BranchUnit).
- **Формы операндов** — то, что декодер обязан разобрать и отдать Execute.
- **Статус** — `v1` (обязательно), `later` (после первой версии), `todo`
  (нужно решение ментора).

## ALU (ТЗ, п. 3.2.3)

| Мнемоники | Формы операндов | Статус |
|---|---|---|
| ADD, SUB | Rw, Rw / Rw, #data / Rw, mem | v1 |
| ADDB, SUBB | Rb, Rb / Rb, #data / Rb, mem | v1 |
| ADDC, SUBC | Rw, Rw | v1 |
| ADDCB, SUBCB | Rb, Rb | v1 |
| CMP, CMPB | Rw, Rw / Rw, #data / Rw, mem | v1 |
| NEG, NEGB | Rw / Rb | v1 |
| MUL, MULU | Rw, Rw (результат в MD) | v1 |
| DIV, DIVU, DIVL, DIVLU | Rw (делимое в MD) | later |

`Rb` — байтовый регистр (`RL0..RH7`), `Rw` — словный (`R0..R15`).

## BitProcessor (ТЗ, п. 3.2.4)

| Мнемоники | Формы операндов | Статус |
|---|---|---|
| AND, OR, XOR | Rw, Rw | v1 |
| ANDB, ORB, XORB | Rb, Rb | v1 |
| CPL, CPLB | Rw / Rb | v1 |
| SHL, SHR, ASHR | Rw, #data4 | v1 |
| ROL, ROR | Rw, #data4 | v1 |

## Stack и BranchUnit (ТЗ, п. 3.2.5)

| Мнемоники | Формы операндов | Статус |
|---|---|---|
| PUSH, POP | Rw | v1 |
| CALL, CALLA, CALLI, CALLR, CALLS, PCALL | caddr / rel / reg / seg,caddr | v1 |
| RET, RETS, RETP | — / Rw | v1 |
| JMPA, JMPI, JMPR, JMPS | caddr / reg / rel / seg,caddr | v1 |
| JB, JNB, JBC, JNBC | bitaddr, rel | v1 |

## Память и пересылки

| Мнемоники | Формы операндов | Статус |
|---|---|---|
| MOV, MOVB | Rw, Rw / Rw, #data / Rw, mem / mem, Rw | v1 |
| EXTS, EXTP, EXTSR, EXTPR | #pag / #seg | todo |

`EXTS`/`EXTP` — префиксы: меняют поведение **следующей** инструкции. Если они
входят в v1, декодер перестаёт быть чистой функцией и получает состояние
префиксов. Решение — за ментором.

## Что нужно, чтобы заполнить кодирование

1. Instruction Set Manual, раздел с форматами инструкций и таблицей опкодов
   (2 / 4 / 6 / 8 байт).
2. Соглашение о раскладке полей во втором байте (какой ниббл — источник,
   какой — приёмник) для каждой формы.
3. Правило sign-extend для `rel8` у `JMPR`/`CALLR` и диапазон перехода.
4. Формат битового адреса для `JB/JNB/JBC/JNBC`.
5. Список «неподдерживаемых» опкодов, на которых эмулятор обязан остановиться
   (ТЗ, «Обязательно», п. 9).

## Источники

- Infineon, C166 Instruction Set Manual (архитектура C166 classic).
- ТЗ проекта, раздел 3.2 — состав компонентов и операций.
- Keil C166 — эталонный симулятор для сверки поведения (указан в
  `docs/выбор_архитектуры.md`).
- IDA Pro — нативная поддержка C166, используется как ориентир для дизассемблера.
