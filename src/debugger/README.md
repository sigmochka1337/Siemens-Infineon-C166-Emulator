# Участник 4: Debugger и интеграция

Владение: `src/debugger/`, `src/core/`, `tools/`, корневой CMake/CI и
`tests/test_integration.cpp`. Подключает зависимости и организует Tick; значения
операндов, флаги и цели переходов не вычисляет.

`CpuCore` хранит только состояние управления запуском и последнюю ошибку.
Архитектурное состояние и RAM принадлежат одному `IMachine`. Зависимости
передаются по ссылке и должны жить дольше Core/Debugger.

`Run` проверяет адрес остановки и breakpoint до инструкции. `Step` игнорирует
breakpoint, позволяя пройти его одной командой. Run имеет обязательный конечный
лимит; результат различает лимит, адрес, breakpoint, fault и trap. Адресные
остановки проверяются также на границе исчерпания бюджета.

Trace получает результат попытки Tick и состояние после неё. Нельзя вызывать
из callback повторные Run/Step или изменять core. Получатель trace заимствован;
он должен жить до отключения через `SetTraceSink(nullptr)`.

Для просмотра используйте `Snapshot`, `PeekMemory`, `InspectInstruction`:
они не вызывают гостевых побочных эффектов чтения. Для начального состояния:
`Reset`, `LoadBinary`, `WriteRegister`, `SetEntryPoint`.

Fault/trap фиксируется в core. Повторное исполнение до Reset не выполняет
инструкций. Reset сохраняет программу, но сбрасывает CPU: затем заново задайте
нужное начальное состояние. Изменение регистра или точки входа само по себе не
снимает fault.

Следующие задачи: интерактивный CLI, представление регистров/памяти,
форматирование через IDecoder, экспорт trace. Step-out добавляется через
`FlowKind` и сведения о вызовах; не обещает полноценный unwind произвольного
кода, вручную меняющего стек.
