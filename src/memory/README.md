# Memory — участник 3

Владелец: память, регистры, SFR, трансляция адресов. Контракт —
`src/interfaces/memory.h`. Публичная реализация — `c166::Machine`.

## Выбранное учебное окружение

Это функциональный профиль на основе C166S V1, а не полная модель конкретного
микроконтроллера. Предоставляется 16 MiB памяти. По обычным физическим адресам
доступна RAM; области SFR `00:FE00..FFFF` и ESFR `00:F000..F1FF` обслуживаются
специально. Из SFR сейчас поддержаны DPP0..3, MDH, MDL, CP, SP, STKOV,
STKUN, MDC, PSW. Остальные обращения к SFR/ESFR явно возвращают ошибку.
Код из SFR/ESFR не исполняется.

Банки GPR и системный стек располагаются в DPRAM `00:F200..FDFF`.
Битовая RAM — `00:FD00..FDFF`. Полная банка `CP..CP+31` должна помещаться
в DPRAM: неподдержанное значение CP отклоняется без изменения состояния.
Это диагностическое ограничение окружения для аппаратно неопределённой
конфигурации, а не дополнительный аппаратный trap C166.

Источники: ISM §6.1–6.4, печ. стр. 132–137; SUBS §3.5, стр. 3-46–50,
§3.6.3, стр. 3-61–64, §4.3, стр. 4-5–6.

## Инварианты

- `Rn` хранится только в RAM по адресу `CP + 2*n`.
- `RLn/RHn` сохраняют соседний байт того же GPR.
- Именованные SFR и доступ по физическому адресу используют одно хранилище.
- Память little-endian; нечётное обращение к слову возвращает диагностическую
  причину `IllegalWordAccess`.
- Байтовая запись SFR очищает другой байт, затем применяет фиксированные биты.
- DPP имеют 10 изменяемых бит; CP/SP/STKOV/STKUN сохраняют фиксированные
  старшие биты и чётность. Для CP действует правило SUBS стр. 3-50 о младших
  значениях. У PSW реализована маска `FC7Fh`, у MDC — `00FFh`.
- Запись MDH/MDL устанавливает MDC.MDRIU; CPU-чтение MDL сбрасывает его.
  `Snapshot` и `Peek8` не имеют этого побочного эффекта (SUBS стр. 3-72–74).
- Проверка STKOV/STKUN принадлежит executor и зависит от инструкции.
  Обычная запись SP не вызывает stack trap.
- `ResolveDataAddress` учитывает DPP и активный EXT. Короткая адресация GPR,
  SFR и битов имеет свои правила и не проходит через DPP.
- Обратной однозначной трансляции физического адреса в логический нет.

`Read8/Read16/ReadRegister` — обращения CPU с возможными побочными эффектами.
`Peek8/Snapshot` — наблюдение отладчиком без побочных эффектов. Методы
`Resolve*` только вычисляют адрес; неподдержанный SFR диагностируется при
фактическом чтении или записи. `SetPC` — привилегированная операция ядра и
отладчика; нечётный адрес отклоняется, автоматического переноса CSP нет.

## Сброс и загрузка

Конструктор обнуляет RAM. `Reset` сохраняет RAM и загруженный бинарник, сбрасывая
PC, EXT и реализованные SFR: CP/SP=`FC00h`, STKOV=`FA00h`, STKUN=`FC00h`,
DPP0..3=`0,1,2,3`, PSW/MDH/MDL/MDC=`0`. GPR являются RAM и сохраняются.
`LoadBinary` сначала проверяет весь диапазон, включая пересечение SFR/ESFR,
и только затем копирует байты. Начальные SFR задаются через `WriteRegister`.

## Следующие задачи участника

Расширение карты регионов и устройств MMIO; режимы прав доступа; уточнение
профиля конкретного MCU; дополнительные SFR и их аппаратные эффекты. Конвейерные
задержки CP/DPP/SP, кольцевой стек и периферийные устройства пока не моделируются.
Контрактные проверки находятся в `tests/test_memory.cpp`.
