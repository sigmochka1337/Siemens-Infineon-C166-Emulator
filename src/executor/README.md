# Executor — участник 1

Владелец `Executor`, арифметики и PSW, разрешения и чтения операндов,
условий, переходов, стека, семантики traps и EXT. Использует только `IMachine`.
Memory вычисляет физические адреса и обеспечивает согласованность RAM/GPR/SFR;
executor определяет момент обращения и порядок pre-decrement/post-increment.

**Только executor меняет PC после инструкции.** Fetcher, decoder и `CpuCore`
его не увеличивают. `instruction.pc` должен совпадать с текущим PC.
Неподдержанные формы отклоняются до изменения машины. Ошибки доступа не
обещают отката уже совершённых операций; состояние после ошибки доступно
через snapshot, а дальнейшее исполнение останавливает core.

Первый работающий срез: NOP; MOV Rw,Rw; MOV Rw,#data16;
ADD Rw,Rw; JMPR cc,rel8. Конкретные кодировки находятся в
[`docs/isa_scope.md`](../../docs/isa_scope.md). Остальные значения `Opcode`
предоставляют общий словарь для дальнейшего расширения, но пока возвращают
`kUnsupportedInstruction`.

Семантика проверена по ISM: ADD — печатная стр. 41, MOV — 95–96,
условия — 38, JMPR — 91 и 140. MOV меняет E/Z/N, сохраняет C/V;
ADD меняет E/Z/V/C/N. E определяется исходным операндом.
Остальные биты PSW сохраняются. Следующие byte-формы должны работать и с RHn,
а ADDC/ADDCB требуют накопительного Z; эти формы ещё не реализованы.

EXT-последовательность хранится в машине: успешная обычная инструкция
уменьшает счётчик, при нуле очищается режим и выбор ESFR. Сами EXT-команды
пока не реализованы. При их добавлении счётчик задаёт 1–4 следующие инструкции,
а новая EXT заменяет текущую последовательность (ISM, стр. 39, 78–85, 138).

При выходе итогового PC за сегмент учебный профиль диагностически
останавливается с `kSegmentBoundary`. CSP не увеличивается автоматически.
Это ограничение профиля, а не утверждение об аппаратном trap. Для JMPR
цель вычисляется от следующей инструкции со знаковым смещением в словах.

Следующие этапы: адресуемые формы MOV/ALU → byte-формы → стек и CALL/RET →
bit-команды → EXT и traps. Для каждой формы нужны байтовый тест decoder,
тест семантики executor и сквозной тест через core.
