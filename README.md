# Учебный эмулятор C166

Проект разделён между четырьмя участниками. Общий контракт находится в
`src/common/` и `src/interfaces/`, реализации модулей собираются независимо.

| Участник | Каталоги | Ответственность |
| --- | --- | --- |
| Executor | `src/executor/` | Семантика инструкций, PSW, PC, стек, состояние EXT |
| Decoder + Fetcher | `src/decoder/` | Кодировки, длины 2/4, выборка, типизированные операнды, форматирование |
| Memory | `src/memory/` | Единое состояние CPU/RAM/SFR, регистровые алиасы, трансляция адресов |
| Debugger | `src/debugger/`, `src/core/`, `tools/` | Цикл ядра, композиция модулей, run/step, остановки, trace, будущий CLI |

Подробности: [архитектура и правила интеграции](docs/architecture.md),
[профиль процессора](docs/cpu_profile.md),
[реальные поддержанные формы инструкций](docs/isa_scope.md),
[Fetch/Decode](docs/fetch_decode.md).

## Сборка и проверка

Нужны CMake 3.20+ и компилятор C++20. Внешних библиотек нет.

```sh
cmake -S . -B build -DCMAKE_BUILD_TYPE=Debug
cmake --build build -j
ctest --test-dir build --output-on-failure
./build/c166_demo
```

Демонстрация исполняет настоящие кодировки `MOV R0,#1; MOV R1,#2; ADD R0,R1`
и останавливается перед следующим `JMPR`. Ожидается `R0=3`, `R1=2`, `IP=10`.
Это рабочий минимальный срез архитектуры; полный набор инструкций C166,
периферия и интерактивный CLI ещё не реализованы.

Отдельные цели: `c166_executor`, `c166_decoder`, `c166_memory`, `c166_debugger`,
`c166_core`. Проверка стиля: `./scripts/check-format.sh`.

## Документация

Аппаратные свойства сверяются с локальными руководствами Infineon:
`docs/c166-ism-v2.0-2001-03.pdf` и `docs/c166-subs-um-v1-6-b.pdf`.
Профиль проекта явно ограничивает область их реализации.

`docs/tz.typ` и `docs/Техническое задание.pdf` сохранены как исходное студенческое
ТЗ. Они расходятся по версии и содержат требования, ещё не приведённые к текущей
архитектуре. Для разработки используйте документы по ссылкам выше; исходное ТЗ
нужно согласовать с ними перед следующей публикацией PDF.
